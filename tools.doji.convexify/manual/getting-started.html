    Getting started

    Import the 'Shared Sample Assets', then the 'Basic Sample' or the 'Async Sample' in the Package Manager to see how to use the library. The samples need the Universal Render Pipeline (URP). All types are in the Doji.Convexify namespace.

    Essentially, this is the code necessary to calculate a convex decomposition:

    vhacd = new VHACD();
ConvexDecomposition cd = vhacd.Compute(mesh, 0);
vhacd.GenerateColliders(cd, gameObject);

    That's really all there is to it. To configure the precision/speed of the calculations, there's a 'Parameter' instance you can modify like so:

    vhacd.Parameters.Resolution = 64;

    This will increase the resolution that the algorithm uses, which will result in a more precise decomposition, but will also take longer to run. For more information on all the settings visit the documentation on the link above.

    Async

    ComputeAsync does not block the main thread. The decomposition runs as Burst jobs, and the method waits across frames. Call it on the main thread.

    ConvexDecomposition cd = await vhacd.ComputeAsync(mesh, 0);
await vhacd.GenerateCollidersAsync(cd, gameObject);

    This works on all platforms, also on the Web. A Web build without multithreading runs the jobs on the main thread, so a frame can take longer.

    Native arrays and jobs

    Use Schedule to give the input as native arrays or as Mesh.MeshData, and to get the result as native arrays. This is for job and DOTS code.

    using Mesh.MeshDataArray data = Mesh.AcquireReadOnlyMeshData(mesh);
ConvexDecompositionHandle handle = vhacd.Schedule(data[0], 0);

// Later, on the main thread:
if (handle.IsCompleted) {
    using NativeConvexDecomposition result = handle.Complete(Allocator.Temp);
    for (int h = 0; h < result.HullCount; h++) {
        NativeArray<float3> points = result.GetPoints(h);
        NativeArray<int> indices = result.GetIndices(h); // into points
    }
}

    Obey these rules:

    • Call Schedule, Complete, and Dispose on the main thread.
    • Call Complete or Dispose one time for each handle. Both wait for the jobs.
    • Schedule(Mesh.MeshData, ...) copies the mesh data. You can dispose the mesh data array after the call.
    • Schedule(NativeArray<float3>, NativeArray<int>, ...) does not copy the arrays. Do not change or dispose them until the handle is complete. Give the jobs that write them as dependsOn.
    • Dispose the NativeConvexDecomposition when you do not need it.

    GenerateColliders and GenerateCollidersAsync also accept a NativeConvexDecomposition. They read it before they return, so you can dispose it after the call. ToConvexDecomposition converts the result to a ConvexDecomposition.

    Colliders

    GenerateColliders makes one game object with a convex MeshCollider for each hull. The PhysX bake of the meshes runs as a parallel job on worker threads, and the method waits for it. GenerateCollidersAsync does not wait on the main thread. On the Web without multithreading, the bake runs on the main thread.

    Burst

    The decomposition needs Burst compilation for good performance. If you disable Burst compilation (for example with Jobs > Burst > Enable Compilation), the jobs run without Burst. They are much slower, and the hulls can be slightly different.

    Input meshes

    Convexify works best with closed meshes that have a volume. Some other input is handled as follows:

    • Flat meshes (for example a quad, a sign, or a card): if all vertices are within half a voxel of one plane, the mesh is flat. A flat mesh with a convex outline gives one hull. A flat mesh with a concave outline gives a small number of hulls. The hulls are one voxel thick, so the thickness changes with Resolution.
    • Meshes without surface area (no triangles, or all points on one line): the result has no hulls, and Convexify logs a warning.
    • Thin curved meshes (for example a bent sheet): these are not flat, so they can give many thin hulls.

    Compute returns only hulls that PhysX can use as convex colliders. GenerateColliders and GenerateCollidersAsync make one collider for each hull.
